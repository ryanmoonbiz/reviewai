## 6. 세부 기술 요구사항 및 예외처리 가이드

### 6.1. CSV 파서 예외처리 규격 (`parser.js`)
* **필수 구현**: CSV 파싱 시 쉼표(`,`)와 큰따옴표(`""`) 처리를 필수적으로 지원해야 합니다. 필드 내에 쉼표가 있을 경우 큰따옴표로 묶인 데이터 전체를 하나의 값으로 정상 처리해야 합니다.
* **권장 구현**: 큰따옴표 내부의 줄바꿈(개행) 처리는 권장 사항입니다. 만약 파서 구조상 완벽한 개행 처리가 어려울 경우, 업로드 영역 하단에 `"줄바꿈이 포함된 리뷰는 붙여넣기 입력을 권장합니다."`라는 안내 메시지를 눈에 띄게 배치해 예외 상황을 안전하게 우회하도록 합니다.
* **인코딩 제한**: 이번 S2 UX02 단계에서는 **UTF-8 인코딩 형식의 CSV 파일만 정상 지원**하는 것으로 정의합니다. CP949(EUC-KR) 자동 감지는 구현 스펙에서 제외하되, 업로드 영역 근처에 `"UTF-8 인코딩 형식의 CSV 파일만 지원합니다."`라는 경고 문구를 명시해 사용자 실수를 미연에 방지합니다.
* **파일 용량 및 업로드 제어**: 단일 업로드 파일의 최대 용량은 **2MB**로 강제 제한합니다. 2MB를 초과하는 CSV 파일 업로드 시 즉시 처리를 거부하고 명확한 오류 피드백 UI를 노출합니다.

### 6.2. sessionStorage 저장 제한 및 가이드라인
* 파싱 완료된 데이터를 `sessionStorage`에 보존할 때 아래 보안 및 데이터 수칙을 철저히 준수해야 합니다.
  * **실제 고객 개인정보가 포함된 테스트 데이터를 사용하지 않습니다.**
  * **100건 이하의 데이터가 들어왔을 때만** sessionStorage에 정상 저장을 진행합니다.
  * **101건 이상의 데이터가 들어오거나 업로드될 경우, 전체 저장을 철저히 차단하고** sessionStorage에 아무것도 저장하지 않은 상태로 카카오 상담 및 견적 안내 모달을 노출해야 합니다.
  * 새로운 CSV 업로드 또는 새로운 분석 시작 시 기존 sessionStorage 데이터는 완벽히 **초기화(clear)**합니다.
  * 개인정보 자동 탐지 및 마스킹 기능은 UX02 범위에서 제외하고 후속 백로그로 분리하므로, **이번 단계에서는 개발하지 않습니다.**
  * `.env`, 토큰, API Key 등 어떠한 시스템 민감정보도 `sessionStorage`에 절대 저장하지 않습니다.

### 6.3. 카카오 상담 신청 모달 및 CTA 명확화
* 실제 카카오 상담 채널 API 또는 외부 채널 연동은 진행하지 않으며, 모달 UI와 상담 요청 유도용 CTA 문구 마크업까지만 완성합니다.
* 실제 연결 링크는 `#` 또는 placeholder 처리해 주시고, HTML 내에 해당 CTA anchor(`<a>`) 또는 `<button>` 태그 근처에 아래 주석을 명시해 두십시오.
  ```html
  <!-- 실제 카카오 상담 채널 URL은 라이언 대표 확정 후 연결한다 -->
  ```

## 8. 점진적 Git 승인 절차 (Git Release Gates)

덱스는 개발 완료 후 임의로 커밋이나 푸시를 진행하지 않으며, 아래의 명확히 격리된 단계를 거쳐야 합니다.

* **개념 정리**:
  * **Commit(커밋)**: 내 컴퓨터(로컬) 안에서만 개발 이력의 안전한 작업 스냅샷을 찍어 저장하는 것입니다.
  * **Push(푸시)**: 내 컴퓨터 내의 로컬 커밋 스냅샷들을 원격 GitHub 저장소에 업로드하는 것입니다.
* **진행 단계**:
  1. **[1단계] 로컬 구현 및 1차 상태 보고**: 코드 개발을 완료한 후, 커밋을 생성하지 않은 상태에서 `git status` 결과와 변경 파일 목록을 담아 **비티에게 1차 보고**합니다.
  2. **[2단계] 로컬 커밋 실행**: 비티가 코드 및 파일 상태를 확인하고 승인하면, 지시에 따라 로컬 커밋을 실행합니다.
     * 커밋 메시지: `feat: S2 UX02 landing and forms`
  3. **[3단계] 원격 Push 및 PR 생성**: 빌(PO)의 로컬 상태 최종 검수 및 승인 지시가 내려지면, 원격 저장소에 push를 실행하고 GitHub PR을 생성합니다.
     * PR 제목: `[S2-UX02] Landing and input forms`
  4. **[4단계] 최종 병합**: 라이언(대표)의 최종 승인 완료 사인이 떨어지기 전까지는 `main` 브랜치로의 merge는 철저히 금지됩니다.

## 9. PR 6대 증빙 기준 (UX02 전용)
빌(PO)의 원격 검수를 위한 PR 본문 6대 필수 증빙 요건입니다.

1. **로컬 구동 URL**: python3 http.server 기반의 로컬 구동 URL 확인.
2. **모바일 반응형 검수 캡처**: iPhone SE 375px 및 표준 390px 크기에서 아래 3개 화면의 레이아웃 반응형 캡처 이미지 총 6종 제출.
   * 홈 입력 화면 (기본 상태)
   * CSV 업로드/미리보기 화면 (파싱 미리보기 적용 상태)
   * 101건 초과 시 노출되는 카카오 상담 및 견적 안내 모달 화면
3. **CSV 경계값 테스트 결과 캡처**: 아래 4가지 케이스의 테스트 통과 화면 증빙 제출.
   * **0건**: 텍스트 미입력/미업로드 시 분석 시작 버튼 비활성화 상태
   * **1건**: 1건의 데이터 정상 업로드 및 파싱 미리보기 활성화 상태
   * **100건**: 100건 데이터 정상 업로드 및 활성화 상태
   * **101건**: 101건 이상 데이터 입력/업로드 시 데이터 차단 및 카카오 상담 안내 모달 활성화 여부
4. **금지 표현 grep 검색 결과**: 소스 코드 전체를 대상으로 아래 명령어 검색 결과(검출 0건)의 터미널 출력 화면 첨부.
   * `rg "허위 리뷰|악성 고객|블랙컨슈머|리뷰 삭제 보장|매출 상승 보장|검색 노출 보장|100%|완벽|최상|전격|보장" app data .github`
   * *주의: '100%'나 '보장'은 코드상(예: 100% width, 100건 등) 정상적으로 나타날 수 있으므로, 검색 결과가 나타날 경우 비티와 빌 PO가 과장/오도성 문맥인지 직접 확인 후 최종 PASS를 판단합니다.*
5. **인쇄 미리보기**: 입력/업로드 화면 기준 Cmd+P 인쇄 미리보기 제출 또는 `"UX02 범위 제한으로 리포트 인쇄는 UX05에서 검증"` 문구를 PR 본문에 명시.
6. **최종 수정 파일 요약**: 변경된 파일 전체 목록과 각 파일의 변경 목적 요약.
