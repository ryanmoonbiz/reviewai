# 📋 RAI_OPERATING_RULES.md (프로젝트 운영 원칙)

본 문서는 리뷰와이(Reviewai) 개발 프로젝트의 최상위 운영 원칙을 규정하는 로컬 참조 문서입니다. 노션의 원본 기획 및 운영 원칙을 기준으로 작성되었습니다.

---

## 1. Single Source of Truth (SST) 원칙
* **Notion (전략 및 기획 원본)**: 프로젝트 전략, 기획서, 디자인 시스템, 스프린트 백로그 상태, 비즈니스 가이드라인의 원본입니다.
* **GitHub (코드 및 프로세스 원본)**: 소스 코드, 브랜치 관리, Pull Request(PR) 내역 및 코드 변경 이력의 원본입니다.
* **로컬 docs (실무 참조용 복사본)**: Notion 및 GitHub 원본을 바탕으로 로컬 개발 및 PM 진행 시 빠르게 참조하기 위한 요약 실행 문서입니다.
* **우선순위**: 로컬 및 GitHub의 규칙이 Notion 원본과 상충될 경우, **Notion의 승인된 원본 내용**을 최우선으로 따릅니다.

---

## 2. 기본 협업 프로세스 및 작업 흐름
1. **방향 수립**: 빌(Bill)과 라이언(Ryan)이 사업적 목표와 큰 개발 방향을 설정합니다.
2. **기획 검토**: 개발 PM 겸 QA 리드인 비티(Biti)가 Notion 문서를 MCP로 분석 및 이해합니다.
3. **계획 수립**: 비티는 사전 리서치와 개발 계획 초안을 수립하여 보고합니다.
4. **리드진 승인**: 빌과 라이언이 개발 범위와 가드레일을 검토 후 공식 승인합니다.
5. **작업 분해**: 비티가 최종 승인된 기획 범위를 기준으로 개발자 덱스(Dex)가 수행할 Story/Task 단위의 백로그를 상세화합니다.
6. **개발 실행**: 덱스는 분할된 작업 지시에 따라 소스 코드를 작성하며, 완료 후 PR을 생성합니다.
7. **1차 QA**: 비티가 기능 검수 및 QA를 거쳐 노션 백로그에 진행사항 및 결과를 기록합니다.
8. **사업성 검토**: 빌이 사업적 리스크, 리포트 품질, 비즈니스 가치를 재검토합니다.
9. **최종 승인**: 라이언이 최종 프로덕트 확인 후 승인하여 배포 여부를 결정합니다.

---

## 3. 예외 상황 및 범위 관리 (Blocked 수칙)
아래의 예외 상황이 감지되면 개발자는 즉시 작업을 중단하고 에스컬레이션해야 합니다:
* 기획 및 승인된 스코프를 초과하는 기능 구현 요구 시
* 데이터베이스 스키마 및 데이터 구조의 대대적인 변경 필요 시
* 기존에 개발된 UI나 플로우에 부작용(Regression)이 예상될 때
* 크롤링, 외부 연동 등 API 수집 관련 기술적 리스크 발생 시
* Gemini API 등 호출 비용이 과도하게 증가할 여지가 있을 때
* 마케팅 및 법적 금지 표현, 가이드라인 위반 요소 발견 시

### [대응 프로토콜]
1. 개발 실행을 즉시 중단합니다.
2. 해당 백로그의 스크럼 상태를 `Blocked`로 변경합니다.
3. 비티가 원인 분석과 기술적 대안을 노션에 기록합니다.
4. 빌이 사업적 영향도 및 리스크를 검토합니다.
5. 라이언이 재개, 보류, 범위 축소(De-scope) 중 의사결정을 최종 승인합니다.

## 4. 운영 권한 전환 및 비티 역량 검증 게이트 (RAI-S2-OPS01)
* **UX01~UX02 단계**: 빌과 라이언의 강한 검수/승인 게이트를 유지합니다. 모든 덱스 지시서는 빌의 검수와 라이언의 승인을 받아야 발송할 수 있습니다.
* **UX02 완료 및 검증 실행 (RAI-S2-OPS01)**: UX02 작업 완료 후, 비티의 개발팀장 역량(지시서 품질, 범위 통제, 보안 인식, QA 역량, 리스크 보고, 라이언 피로도 감소)을 종합 평가합니다.
* **UX03 이후 반자동화 전환**: 검증 통과 시, Notion을 중심으로 비티가 덱스에게 지시서를 작성하고, 덱스가 작업 후 결과를 Notion/PR에 기록하며, 비티가 1차 QA를 진행하는 반자동화 프로세스로 이행합니다.
* **라이언 최종 게이트 유지**: 운영 권한이 위임되더라도, **merge 승인, Done 처리, MVP 범위 변경, 외부 API/API Key 관련 작업, 결제/배포/자동화 작업**은 계속해서 라이언 PO의 최종 서명 및 승인이 필수로 작용합니다.
