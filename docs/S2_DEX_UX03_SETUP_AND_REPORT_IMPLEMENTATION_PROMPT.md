## 7. 점진적 Git 승인 절차 (Git Release Gates)

덱스는 개발 완료 후 임의로 커밋이나 푸시를 진행하지 않으며, 아래의 명확히 격리된 단계를 거쳐야 합니다.

* **개념 정리**:
  * **Commit(커밋)**: 내 컴퓨터(로컬) 안에서만 개발 이력의 안전한 작업 스냅샷을 찍어 저장하는 것입니다.
  * **Push(푸시)**: 내 컴퓨터 내의 로컬 커밋 스냅샷들을 원격 GitHub 저장소에 업로드하는 것입니다.
* **진행 단계**:
  1. **[1단계] 로컬 구현 및 1차 상태 보고**: 코드 개발을 완료한 후, 커밋을 생성하지 않은 상태에서 `git status` 결과와 변경 파일 목록을 담아 **비티에게 1차 보고**합니다.
  2. **[2단계] 로컬 커밋 실행**: 비티가 코드 및 파일 상태를 확인하고 승인하면, 지시에 따라 로컬 커밋을 실행합니다.
     * 커밋 메시지: `feat: S2 UX03 report UI and binding`
  3. **[3단계] 원격 Push 및 PR 생성**: 빌(PO)의 로컬 상태 최종 검수 및 승인 지시가 내려지면, 원격 저장소에 push를 실행하고 GitHub PR을 생성합니다.
     * PR 제목: `[S2-UX03] Report UI and binding`
  4. **[4단계] 최종 병합**: 라이언(대표)의 최종 승인 완료 사인이 떨어지기 전까지는 `main` 브랜치로의 merge는 철저히 금지됩니다.

## 8. PR 6대 증빙 기준 (UX03 전용)
빌(PO)의 원격 검수를 위한 PR 본문 6대 필수 증빙 요건입니다.

1. **로컬 구동 URL**: python3 http.server 기반의 로컬 구동 URL 확인.
2. **데스크톱/모바일 리포트 화면 캡처**:
   * 데스크톱(1200px)에서 `/report` 가상 뷰의 전체 영역(요약 카드, 탭, 우선 검토 리스트 등) 캡처 1종.
   * 모바일(375px/390px) 뷰포트에서 리포트 레이아웃이 깨지지 않고 표시되는 캡처 각 1종 (총 2종).
3. **입력 ➡️ 리포트 전환 정상 작동 확인**:
   * 홈 화면에서 분석 버튼 클릭 후 로딩 화면을 거쳐 `/report` 가상 뷰로 데이터가 연동되어 전환 렌더링되는 전 과정을 녹화한 동영상 또는 순차적 캡처 증빙 제출.
4. **금지 표현 grep 검색 결과**: 소스 코드 전체 대상 금지 키워드 아래 명령어로 검색 후 결과(검출 0건)의 터미널 출력 화면 첨부.
   * `rg "허위 리뷰|악성 고객|블랙컨슈머|리뷰 삭제 보장|매출 상승 보장|검색 노출 보장|100%|완벽|최상|전격|보장" app data .github`
   * *주의: '100%'나 '보장'은 코드상(예: 100% width, 100건 등) 정상적으로 나타날 수 있으므로, 검색 결과가 나타날 경우 비티와 빌 PO가 과장/오도성 문맥인지 직접 확인 후 최종 PASS를 판단합니다.*
5. **인쇄 미리보기 명시**: "UX03 범위 제한으로 리포트 인쇄 스타일 완성은 UX05에서 최종 검증" 문구를 PR 설명에 명시 (또는 현시점의 임시 인쇄 미리보기 화면 첨부).
6. **최종 수정 파일 요약 및 UX02 회귀 테스트 증빙**:
   * 변경된 파일 전체 목록과 각 파일의 변경 목적 요약.
   * UX03 구현 완료 후에도 기존 UX02 홈 화면의 0건(비활성), 1건(정상 미리보기), 100건(정상 미리보기), 101건(차단 및 카카오 상담 모달 노출) 입력 제한 기능이 여전히 정상 작동함을 입증하는 테스트 결과 캡처 제출.
