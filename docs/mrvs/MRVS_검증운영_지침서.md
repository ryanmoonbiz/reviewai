# MRVS 검증운영 지침서

문서 버전: v0.1  
프로젝트: ReviewAI / 리뷰와이  
대상 백로그: RAI-S2.1-VAL01 — MVP 시장 반응 가능성 점수화 및 검증 체계 수립

## 1. 검증 목적

MRVS는 Market Response Validation Score의 약자다.

이 검증 체계는 다음 질문에 답하기 위해 사용한다.

- 현재 MVP가 실제 시장에서 반응을 만들 가능성이 있는가?
- S3 배포·결제 단계로 바로 가도 되는가?
- S2.1에서 먼저 보강해야 할 운영, 데이터, 어드민, UX, QA 백로그는 무엇인가?
- 이 MVP 검증 방식을 다른 카피 개발 수익화 프로젝트에도 반복 적용할 수 있는가?

## 2. 참여 역할

| 평가자 | 역할 | 주요 관점 | 제출 방식 |
|---|---|---|---|
| 빌 | PO / 사업성 | 시장 반응, 유료 전환, S3 판단 | 채팅 |
| 잭 | AI 전략 / 자동화 | AI 차별성, 자동화, 반복 수익화 | 파일 또는 JSON |
| 비티 | PM / 운영 | 수동 운영, Notion 기록, QA 체계 | Notion |
| 덱스 | 기술 구현 | DB, 어드민, 기술 리스크 | 채팅 또는 파일 |
| 라이언 | 최종 승인 | 방향 결정 | 승인 |

라이언은 점수 평가자가 아니라 최종 승인자다.

## 3. 평가 원칙

- 각 평가자는 다른 평가자의 점수를 먼저 보지 않고 독립 평가한다.
- 실제 시장에서 고객 행동이 발생할 가능성을 기준으로 평가한다.
- 근거가 부족한 항목은 낮게 평가한다.
- 점수와 함께 근거, 리스크, 추천 백로그를 반드시 작성한다.
- 결과는 점수보다 근거가 더 중요하다.

## 4. MRVS 점수 체계

총점은 100점이다.

| 항목 | 배점 | 핵심 질문 |
|---|---:|---|
| 문제 강도 | 15 | 고객이 이 문제를 지금 해결하려 하는가? |
| 타깃 선명도 | 10 | 가장 먼저 쓸 고객이 명확한가? |
| 가치 제안 | 15 | 첫 화면과 리포트만 보고 써볼 이유가 생기는가? |
| 행동 전환 | 15 | 관심이 실제 입력, 생성, 상담 클릭으로 이어지는가? |
| 지불 의사 | 15 | 고객이 돈을 낼 이유가 있는가? |
| 신뢰/품질 | 10 | 고객에게 보여줘도 신뢰를 줄 수 있는가? |
| 운영 가능성 | 10 | 고객이 들어오면 수동으로라도 놓치지 않고 처리할 수 있는가? |
| 확장/반복 가능성 | 10 | 다른 카피 개발/수익화 MVP에도 반복 적용 가능한가? |

## 5. 점수 해석 기준

| 총점 | 판단 | 의미 |
|---:|---|---|
| 85점 이상 | S3 진입 후보 | 시장 테스트 확대 가능 |
| 70~84점 | 조건부 파일럿 | S2.1 보강 후 S3 판단 |
| 55~69점 | 보완 필요 | 문제, 타깃, 가격, 운영 중 약점 보완 필요 |
| 55점 미만 | 재검토 | 포지셔닝 또는 타깃 전환 필요 |

## 6. 실행 프로세스

1. 비티가 Notion에 MRVS 검증 페이지와 평가 결과 DB를 준비한다.
2. 빌, 잭, 비티, 덱스가 각자 독립 평가한다.
3. 잭처럼 Notion 접근이 어려운 멤버는 파일 또는 JSON으로 제출한다.
4. 비티가 모든 결과를 MRVS Evaluation Results DB에 입력한다.
5. 빌이 채팅창에서 종합 분석 초안을 작성한다.
6. 라이언이 최종 승인한다.
7. 비티가 승인된 최종본을 Notion에 반영한다.
8. 점수가 낮은 항목을 기준으로 S2.1 백로그를 확정한다.

## 7. Notion 편집 규칙

- 제목 2 블록 사용
- 제목토글 3 적극 사용
- 중요/알림 문구는 콜아웃으로 작성하고 색상 활용
- 머리말 기호 사용
- 불필요한 마크다운 볼드 표식 사용 금지
- JSON 제출 양식은 코드 블록 사용
- 평가표와 점수 비교는 표 사용
- 결과 및 인사이트는 제목 2 블록으로 별도 작성
- 필요 시 일반 문단, 구분선, 체크리스트, 콜아웃 블록 사용
