# S1_dex_work_contract.md v0.2 (스프린트 2 UX/UI 개발 덱스 작업 계약서)

본 계약서는 리뷰와이(Reviewai) 서비스의 스프린트 2(S2) UX/UI 병렬 개발 단계에서 개발자 덱스(Dex)가 준수해야 할 작업 범위, 완료 기준, 품질 검증 요건 및 관리 규칙을 정리한 작업 계약 기준서입니다.

> [!WARNING]
> **주의**: 본 계약서는 스프린트 2 개발을 위해 덱스에게 전달할 작업 계약서 초안입니다. 본 ST09 단계에서는 실제 앱 코드 구현, scaffold 생성, GitHub 브랜치 생성, PR 발행 또는 개발자 덱스의 실제 구현 실행을 수행하지 않습니다.

---

## 1. 계약 개요
* **본 계약서의 목적**: 스프린트 2 UX/UI 개발의 기획 정합성 유지, 임의 디자인 배제 및 품질 일관성 유지를 목표로 개발 작업 규칙을 합의합니다.
* **적용 스프린트**: S2 (스프린트 2)
* **적용 대상**: `RAI-S2-UX01`부터 `RAI-S2-UX05`까지의 총 5대 개발 대백로그
* **성격**: 스프린트 2 공식 개발 수행 가이드이자 최종 인수 및 승인 척도가 되는 기준서입니다.

---

## 2. 덱스 역할과 작업 원칙
* **기획 정합성 우선**: 덱스는 사전에 합의되고 기획된 문서(`S1_PRD_V1_6.md` v0.3, `S1_DEX_UX_UI_TASK_SPEC.md` v0.3 등) 범위 내에서만 수정 작업을 진행합니다.
* **임의 추가 제한**: 기획서에 명시되지 않은 임의 디자인 요소(컬러, 그라데이션, 확대 애니메이션 등), 자의적인 기획 카피 수정, 기획에 포함되지 않은 기능(자동 답글 등록, PG 실결제창 등)을 임의로 추가하는 행위는 인정되지 않습니다.
* **에스컬레이션**: 작업 도중 기획적 모호함이나 기술적 마찰 요인이 발생할 경우, 덱스는 독자적인 판단으로 코드를 수정하지 않고 빌(QA/검수 리드)과 라이언(라이언 PO)에게 문의하여 승인을 획득한 뒤 반영합니다.

---

## 3. 형상 관리 규칙
* **main 브랜치 관리**: 덱스는 베이스라인 코드에서 분기하여 작업을 진행하며, `main` 브랜치에 직접 push하는 행위는 금지됩니다. 모든 코드는 Pull Request(PR) 및 빌/라이언의 검수 후 merge됩니다.
* **작업별 브랜치 분기 규칙**:
  * `RAI-S2-UX01` (디자인 토큰/공통): `feature/s2-ux01-token`
  * `RAI-S2-UX02` (랜딩 페이지 구현): `feature/s2-ux02-landing-submit`
  * `RAI-S2-UX03` (리포트 시각 계층): `feature/s2-ux03-report`
  * `RAI-S2-UX04` (모바일 반응형 검수): `feature/s2-ux04-mobile`
  * `RAI-S2-UX05` (인쇄 레이아웃): `feature/s2-ux05-print`
* **브랜치 생성 유예**: 본 ST09 기획 설계 단계에서는 실제 GitHub 브랜치 생성을 실행하지 않고 명명 규칙 합의에만 국한합니다.

## 4. S2 작업 범위 및 7대 필수 필드

1. **작업 목적**: 서비스 전체의 테마 일관성과 레이아웃 통일성을 위해 공통 CSS 변수와 UI 기본 골격을 구성합니다.
2. **입력 파일/데이터**: `S1_DEX_UX_UI_TASK_SPEC.md` v0.3 내 4.1절 디자인 토큰 상세 기준.
3. **수정 가능 범위**: `index.css` (CSS 변수 `:root` 및 공통 컴포넌트 클래스), `index.html` (Header/Footer 마크업 영역).
4. **완료 기준**:
   - Primary(#1D4ED8), Kakao CTA(#FEE500), Success(#16A34A), Danger(#DC2626) 등 지정 색상 변수 선언 완료.
   - 타이포그래피 Pretendard 폰트 위계 및 라운드 반경 변수(`border-radius` 12px/8px) 선언 완료.
   - 헤더(Reviewai 로고 및 라우팅 링크 구조) 및 카피라이트 풋터 마크업 구현 완료.
   - 모든 링크, 버튼, 탭 전환 영역의 최소 가로/세로 영역 **44px 이상** 확보 완료.
5. **QA 기준**: `QA-MB-06` 터치 타깃 최소 너비 대조 검수.
6. **금지 사항**: 사양서에 지정되지 않은 임의의 원색(빨강, 파랑 등) 또는 그라데이션을 CSS 변수로 마음대로 추가하는 행위 금지.
7. **PR 증빙**: 공통 CSS 변수 목록 및 `index.html` 레이아웃 구조 마크업 캡처.

### 4.2. [RAI-S2-UX02] 랜딩 페이지 구현 및 QA
1. **작업 목적**: 서비스 가치 전달과 CSV 파일 입력을 위해 7대 레이아웃 섹션 및 드롭존 피드백을 마크업합니다.
2. **입력 파일/데이터**: `S1_LANDING_REPORT_DESIGN_DIRECTION.md` v0.4 내 3~4장 구조.
3. **수정 가능 범위**: `index.html` (Home/Landing body 구역), `/submit` 라우팅 뷰 마크업 및 JS 파싱 스크립트.
4. **완료 기준**:
   - 7대 레이아웃 시퀀스(헤더-히어로-가치카드-샘플미리보기-추천-단일상품-풋터CTA) 순서대로 마크업 배치 완료.
   - CSV 전용 드롭존 구현 완료 (마우스 드래그 오버 시 블루 `#1D4ED8` 테두리 피드백 활성화).
   - 파일 첨부 성공 시 실제 파일명(예: `reviews.csv`) 및 파싱 건수(예: `총 8 건 파싱 완료`) 피드백 출력 완료.
   - 필수 열(`reviewText`, `rating`) 감지 성공 시 녹색 체크 배지 활성화, 누락 시 적색 테두리 경고 피드백 및 Empty State 출력 완료.
   - 101건 이상 파일 감지 시 흐림 필터(`backdrop-filter: blur(4px)`)를 적용한 Limit Modal 호출 완료 및 내부 카카오 CTA(#FEE500) 배치 완료.
   - 샘플 데이터 불러오기 버튼 조작 시 15행의 Mock 데이터 즉시 로딩 및 15건 파싱 피드백 활성화 완료.
5. **QA 기준**: `QA-HM-01~06`, `QA-IP-01~07` 검수 목록 대조.
6. **금지 사항**: CSV 외 타 확장자 지원 명시 금지, 100건 초과 시 위압적인 이용정지 어구 사용 금지, PG사 결제 UI 편법 임의 삽입 금지.
7. **PR 증빙**: 파일 첨부 전/후 화면 캡처, 필수 컬럼 에러 발생 상태 화면 캡처, Limit Modal 호출 화면 캡처, 샘플 데이터 로딩 확인 로그.

### 4.3. [RAI-S2-UX03] 리포트 시각 계층 구현 및 QA
1. **작업 목적**: 생성된 분석 정보를 한눈에 인지할 수 있도록 표준 일시 표기, 4대 지표 고정 및 탭 전환 콘텐츠 영역을 구현합니다.
2. **입력 파일/데이터**: `S1_LANDING_REPORT_DESIGN_DIRECTION.md` v0.4 내 5장 및 `S1_UX_UI_REFERENCE_RESEARCH.md` v0.4.
3. **수정 가능 범위**: `/report` 라우팅 화면 마크업, CSS 및 탭 제어 JS 로직.
4. **완료 기준**:
   - 리포트 생성일시 `YYYY-MM-DD HH:MM` 포맷 적용 완료.
   - 상단 4대 핵심 요약 지표(총 분석 리뷰 수, 평균 별점, 주요 부정 키워드 수, 검토 우선 리뷰 수) 그리드 배치 완료.
   - `[탭 1]` 오늘의 요약 3종 카드(전체 상태 요약 -> 부정 키워드 분석 -> 실행 조치 제안) 세로 계층 배치 완료.

   - `[탭 2]` 4종 브랜드 톤(공손/정중, 친근/감사, 격식/전문, 위트/감성) 전환 제어 및 수동 복사용 `[클립보드로 복사하기]` 버튼 동작 완료.
   - `[탭 2]` 답변 카드 내부에 `[민감 표현 감지 - 수동 검수 필수]` 주황색 가드레일 배지(`#FEF3C7` 배경, `#D97706` 텍스트) 마크업 완료 (단, 상단 지표 카드에는 감지 건수 등 노출 배제).
5. **QA 기준**: `QA-RP-01~07` 검수 목록 대조.
6. **금지 사항**: 오늘의 요약 3종 순서 뒤바꾸기 금지, AI 답변 스토어 자동 등록/자동 전송 기능 임의 마크업 금지, 상단 지표 카드 내 키워드 TOP 5 배출 금지 (TOP 칩은 탭 1 내에 격리 배치).
7. **PR 증빙**: 리포트 상단 4대 지표 캡처, 탭 1 요약 및 적색 강조선 캡처, 탭 2 민감 배지 마크업 및 클립보드 복사 실행 로그.

1. **작업 목적**: iPhone SE 등 좁은 뷰포트 환경에서 요소가 밀리거나 깨지는 레이아웃 오류를 방지하고 모바일 터치 오동작을 통제합니다.
